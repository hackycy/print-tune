# 捷印 PrintTune · 方案讨论纪要

> **项目**：打印驱动配置离线导出/导入工具
> **产品线背景**：票务窗口购票系统（Windows 售票终端 + 票据打印机）
> **原始讨论**：WorkBuddy 对话分享页《规划打印驱动设置软件方案》
> 链接 https://workbuddy.link/p/fHiuQQXK5r8ewY8mfXnHCP
> **整理时间**：2026-10-24
> **性质**：讨论过程与结论留档，不是最终设计文档；技术细节仍以验证结果为准。

---

## 0. 一句话结论

**可以做，且值得做。** 产品形态最终收敛为：一个**纯离线的 Windows 单机小工具**，把「已调好的打印首选项」完整导出成配置文件，到客户电脑一键导入并写回驱动。

本质不是"驱动配置生成器"，而是**打印首选项的完整快照与恢复（DEVMODE 快照）**——不做兼容所有打印机的万能配置器。

---

## 1. 背景与痛点

- 产品是票务窗口购票系统，打印链路本身已经完善。
- 但每个客户接入的打印机型号/驱动都不同，打印首选项（纸张、浓度、切刀、钱箱……）各不相同。
- 现状：**每次都要远程到客户电脑手动配置**。
- 痛点：一旦某台机器漏配或配置被改动，就要一遍遍远程调试，人力成本高、响应慢、现场体验差。

**目标**：配置一次 → 保存 → 到别的电脑导入即可用，替代反复远程配置。

---

## 2. 需求的两次收窄（关键决策）

| 阶段 | 定位 | 变更原因 |
|---|---|---|
| A. 初版设想 | 云端配置管理平台 + 门店本地代理 + 驱动适配器（云端统一下发、版本化、可回滚） | 讨论起点，架构最完整 |
| B. 第一次收窄 | **纯离线单机工具**：导出 → 拷走 → 导入 | 用户明确否决服务端：「我不想设计服务端的，我只希望做到离线导入导出，只要能快速配置即可」 |
| C. 定名 | **捷印 / PrintTune**，配置包 `.ptcfg` | 「印枢（PrintHub）」被认为太抽象、不好听 |

> 阶段 A 的架构虽然没被采用，但其中的**兼容性边界判断、DEVMODE 处理思路、三档匹配策略**全部沿用到了离线版，所以保留在本文第 8 节备查。

## 3. 被否决方向的遗留价值（备查）

如果将来要在多门店批量铺开，A 案的三层配置拆分仍然成立：

1. **标准业务配置**（自定义 JSON，与驱动无关）：纸张、方向、份数、缩放、偏移、浓度、切刀、钱箱……
2. **驱动适配配置**（把标准参数翻译成具体驱动能懂的东西）：Windows 通用 DEVMODE 字段、厂商私有参数、厂商 SDK、ESC/POS / TSPL / ZPL 指令、打印队列与端口。
3. **终端绑定配置**：客户 → 门店 → 售票终端 → **打印用途** → 打印机 → 配置版本。

要点：**按"打印用途"绑定，而不是让业务系统写死打印机名称**；换机器时只改绑定关系。

云端/本地各自的职责当时定为：云端存"权威版本"（方案、适用驱动范围、版本、绑定、发布状态、审计），本地存"有效快照"（当前生效配置、上一版可用配置、终端身份、日志）。状态机：

```text
待下发 → 已下载 → 校验通过 → 已应用 → 测试成功
                            ↘ 应用失败 → 已回滚
```

**不要把"客户端收到配置"当成"配置成功"。**

## 4. 技术核心：配置到底存在哪、怎么落进驱动

### 4.1 先纠正一个常见误解

能拿到的**不是"驱动安装文件里的配置"**，而是：

> **某个已安装打印机队列当前保存的打印默认值（PRINTER_INFO_8），或当前 Windows 用户的打印首选项（PRINTER_INFO_9）。**

Windows 驱动本身不保存唯一一份配置；配置可能属于队列、属于用户，或只存在于某一次打印任务里。

### 4.2 DEVMODE 才是载体

Windows 驱动的大部分打印首选项最终都落在 `DEVMODE` 结构里，分为两半：

```text
DEVMODE
├─ Windows 标准字段        ← 可按字段名安全修改
│  纸张编号/宽高、横竖向、份数、颜色、分辨率…
└─ dmDriverExtra 私有数据   ← 只有厂商驱动知道含义
   打印浓度、速度、切刀、钱箱、标签间隙/黑标…
```

因此导出必须完整保存 **`dmSize` + `dmDriverExtra`**，只存标准结构体会把浓度、切刀、钱箱这些真正难配的参数丢掉。

⚠️ `dmFields` 位掩码必须同步置位——只改值不改 `dmFields`，驱动会直接忽略你的修改。

### 4.3 三个写入位置怎么选

| 写入位置 | API | 影响范围 | 权限 | 适用 |
|---|---|---|---|---|
| 打印队列默认值 | `SetPrinter(Level 8)` | 该队列的所有任务 | 通常需管理员 | 专用售票打印机 ✅ 默认选它 |
| 当前用户首选项 | `SetPrinter(Level 9)` | 仅当前 Windows 用户 | 普通用户 | 注意：换用户登录可能就不生效 |
| 单次打印任务 | 打印时显式带入 DEVMODE | 只影响这一张票 | 普通用户 | 最稳，长期演进方向 ⭐ |

**关键判断**：系统首选项适合"存配置 + 给人看"，但**不应是唯一的执行保障**——用户从控制面板改掉、代理以服务账户运行导致写错用户，都会翻车。长期应做到**业务打印时由打印链路显式携带配置**。

### 4.4 标准调用链

```text
OpenPrinter(PRINTER_ACCESS_ADMINISTER)
→ DocumentProperties(读) 取得当前完整 DEVMODE
→ 只改需要的标准字段（不要从零构造 DEVMODE）
→ DocumentProperties(DM_IN_BUFFER | DM_OUT_BUFFER) 让驱动校验/修正/合并私有数据
→ SetPrinter(Level 8 或 9)
→ 再读一遍验证（确认驱动没把值改回去）
→ 打印测试票
```

关键实现细节（易错点）：

- `DocumentProperties` 取大小要**先传 `fMode=0` 探长度**，再分配缓冲区读数据。
- 第 4 步的"驱动校验合并"不能省——它负责校验合法性、修正不支持的值、合并私有设置。要检查返回值并回读确认。
- `GetPrinter` 同样要**调用两次**：第一次拿所需缓冲区大小，第二次读实际数据。
- 调原厂首选项窗口用 `DocumentProperties(..., DM_IN_BUFFER | DM_OUT_BUFFER | DM_IN_PROMPT)`。**第一版靠它白嫖所有厂商的设置界面**，不用自己画。

## 5. 导出：两种来源，都支持

| 方式 | 流程 | 用途 |
|---|---|---|
| ① 直接读当前配置 | `EnumPrinters` → `OpenPrinter` → `GetPrinter(8/9)` → 复制完整 DEVMODE → 附带描述信息 → 导出 | 现场已有机器调好了，直接抓下来当基线 |
| ② 打开原厂界面改完再导出 | 选打印机 → 弹原厂首选项 → 人工调整确认 → 取回 DEVMODE → 测试打印 → 导出 | 先调成模板，再沉淀成标准配置包 |

所以工具同时具备"**备份现有配置**"和"**制作配置模板**"两种能力。

---

## 6. 配置包格式 `.ptcfg`

不使用不透明的二进制 `.dat`，而是"**可读元信息 + Base64 二进制 + 校验值**"的 JSON（扩展名自定义）：

```json
{
  "formatVersion": 1,
  "name": "80mm票据打印机配置",
  "source": "printer-defaults",
  "exportedAt": "2026-10-24T17:45:00+08:00",
  "printerName": "POS-80",
  "driverName": "POS-80 Series",
  "driverVersion": "1.0.0.5",
  "architecture": "x64",
  "osVersion": "Windows 10",
  "devModeSize": 1256,
  "devModeBase64": "……",
  "checksum": "SHA256…"
}
```

- 元信息 → 界面展示 + 兼容性判定
- `devModeBase64` → 完整 DEVMODE（含厂商私有段）
- `checksum` → 发现文件损坏或被篡改
- `source` → 标明来自"打印机默认值"还是"用户首选项"，导入时才知道该写回哪一层

## 7. 导入兼容性：明确三档，不许静默恢复

| 匹配度 | 判定条件 | 处理策略 |
|---|---|---|
| ✅ 完全匹配 | 驱动名称 + 驱动版本 + 系统架构 全一致 | 恢复**完整 DEVMODE**（含私有参数），最可靠 |
| ⚠️ 部分匹配 | 型号接近但驱动版本/架构不同 | 只恢复标准字段（纸张、方向、份数、分辨率），**不复制私有数据**，并提示人工复核浓度、切刀 |
| ⛔ 不兼容 | 不同品牌或驱动差异大 | **禁止应用**，提示"当前打印机与该配置不匹配，请重新选择配置或在驱动设置中重新保存" |

> 刻意**不提供"强制执行"作为主按钮**——那只会把现场问题变得更难排查。

## 8. 第一版范围

### 要做（四个核心动作）

1. **读取现有配置**：枚举本机打印机，显示名称、驱动名、驱动版本、架构、端口
2. **导出配置**：保存完整首选项为 `.ptcfg`
3. **导入并应用**：兼容性三档校验 → 写入队列默认值 / 用户首选项
4. **备份并测试**：应用前自动备份当前配置，应用后打印测试票，明确提示成功/失败原因

配套必做：调出原厂首选项窗口、恢复前自动备份、失败原因可读。

### 第一版明确不做

- 服务端、账号体系、云端下发（已被否决）
- 自动在线升级、自动下载安装驱动
- 自动创建 USB / 网口端口
- 跨品牌私有配置转换
- 自己重绘各家厂商的设置界面
- 解析厂商私有参数的二进制偏移（驱动一升级就废）

### 现场操作目标体验

```text
选择打印机 → 选择配置文件 → 检查兼容性 → 应用 → 测试打印
```

即"**带一个配置文件过去，一键恢复**"。

## 9. 边界与已知坑（必须写进文档和 UI）

**导不出来的东西**（不属于 DEVMODE，需单独处理）：

| 内容 | 能否随配置导出 |
|---|---|
| 打印机驱动安装包 | ❌ 需单独备份 |
| USB / 网口端口配置 | ❌ 通常不能 |
| 打印机 IP 地址 | ❌ |
| 系统自定义纸张表单 | ⚠️ 不一定 |
| 厂商工具写进机身的参数 | ⚠️ 不一定 |
| 厂商软件单独存的注册表配置 | ⚠️ 不一定 |
| 打印模板、票据内容 | — 不属于驱动配置 |

**其他坑**：

- 前提是目标电脑**已装好驱动、已连好打印机队列**；本工具只解决"驱动装好之后的打印首选项配置"。
- 不要无差别修改**系统默认打印机**，会影响客户电脑上的其他软件。
- 私有段跨版本复制风险高，宁可不做也不能静默做。
- 导入后**必须**能测试打印——最终效果（浓度、切刀位置）只有纸面能验证。
- 若将来做后台/服务进程，权限要拆分：服务负责需管理员权限的写入，托盘界面只负责展示和测试，别让整个 UI 长期以管理员跑。

## 10. 未决问题 / 下一步

- [ ] 目标客户现场的主力机型清单（决定适配与验证优先级，先覆盖 2~3 类）
- [ ] 技术栈确认：C# / .NET 8 + WPF（快捷、Windows 打印 API 调用成熟）
- [ ] 配置签名与篡改防护是否第一版就要（`.ptcfg` 的 checksum 只能防损坏，防不住恶意替换）
- [ ] 是否需要一个"配置包备注/适用型号说明"的可编辑字段，方便客服分发
- [ ] 长期是否把业务打印改为"每次打印显式携带 DEVMODE"（最稳，但需改打印链路）

**验收标准（第一版）**：同型号、同驱动的新电脑，不远程也能恢复打印配置；不匹配时明确拦截；应用前有备份、应用后有测试票；全程不需要服务端。
