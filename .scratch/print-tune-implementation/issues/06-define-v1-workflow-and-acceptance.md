# 确定 V1 操作闭环与现场验收标准

Type: grilling
Status: resolved
Blocked by: 01, 02, 03, 04, 05

## Question

首版是否同时支持队列默认值与当前用户首选项的导出/导入，默认写哪一层，是否允许跨层恢复？配置制作、直接备份、原厂设置、导出、导入、自动备份、失败回滚、回读验证和测试票应形成怎样的用户流程；测试票使用工具内置固定内容还是业务模板；成功、部分成功和失败如何呈现；客服分发与现场恢复各自怎样验收？明确哪些能力属于 V1，避免把长期打印链路改造混入本次交付。

## Comments

- 2026-10-25 用户确认：同时支持 Level 8/9，默认只同层恢复，不自动跨层。
- 2026-10-25 用户确认：原厂界面制作模板默认只修改内存工作副本，只有显式“应用到系统”才持久化。
- 2026-10-25 用户确认：写入或回读等技术失败自动回滚；测试作业或纸面效果失败不自动回滚，由用户选择保留或恢复。
- 2026-10-25 用户确认：V1 使用内置 GDI 测试页，技术状态与人工纸面结果分开；业务模板由业务系统另行手动验收。

## Answer

V1 形成“**备份/制作模板 → 导出 → 校验兼容 → 显式应用 → 自动备份 → 写入与同层回读 → 技术失败自动回滚 → GDI 测试 → 人工验收/保留或恢复**”的完整闭环。支持 Level 8 和 Level 9，但默认仅同层恢复；不修改系统默认打印机，不改业务打印链路。

### 1. 配置来源与作用层

- 导出和导入均支持 `printer-defaults`（Level 8）与 `user-defaults`（Level 9）。配置包记录来源层，应用目标默认且只能与该层一致；V1 不提供跨层恢复按钮或隐式回退。
- 专用售票打印机建议 Level 8；只需当前 Windows 用户或明确不希望改队列全局默认时选择 Level 9。UI 显示作用域解释，Level 9 还显示当前交互用户，禁止通过 helper 写错用户。
- Level 8 不可访问时不得悄悄改写成 Level 9；Level 9 失败也不得悄悄写 Level 8。用户需要另一层时，应在目标层重新制作/导出配置，留待未来明确设计跨层迁移。
- 不改变 Windows 默认打印机，不创建队列/端口，不安装驱动，不处理业务打印模板。

### 2. 路径 A：备份现有配置并导出

1. 枚举本机队列，选择打印机并读取队列、端口、驱动名、真实驱动版本、环境/架构等信息；缺失信息明确显示“未知”。
2. 用户显式选择读取 Level 8 或 Level 9，程序读取并深复制完整 DEVMODEW；空配置、长度异常或权限失败均停止并说明。
3. 展示来源层、驱动身份和适用范围。名称、备注、适用说明可编辑，采集的受保护元数据只读。
4. 保存 `.ptcfg`，执行格式与校验生成；重新打开该文件做一次往返校验，避免把导出 IO 错误当成成功。
5. 此路径只备份/导出，不写系统配置。若需要纸面确认，可对读取的工作副本执行 GDI 测试，但不以测试结果改变文件来源元数据。

### 3. 路径 B：使用原厂界面制作模板

1. 从选定 Level 8/9 读取完整工作副本。
2. 以 `DM_IN_BUFFER | DM_OUT_BUFFER | DM_IN_PROMPT` 调原厂界面；只有 `IDOK` 才接受输出，`IDCANCEL` 或失败均放弃修改。
3. 确认后的输出只成为内存工作副本，**不调用 `SetPrinter`，不直接改变系统默认值**。
4. 用户可通过显式 DEVMODE 的内置 GDI 测试页检查工作副本，然后导出 `.ptcfg`。
5. 用户点击“应用到系统”时，不复用一条简化写入路径，而是进入与导入相同的兼容检查、备份、应用、回读和回滚事务。

### 4. 路径 C：导入并应用

1. 选择目标队列和 `.ptcfg`；按配置包票据完成文件、版本、Schema、SHA-256、Base64 和 DEVMODEW 边界校验。
2. 显示来源与目标驱动、来源/目标层、目标 Windows 用户（Level 9）、恢复类型和不可恢复项。完全恢复只开放给实测白名单；受限标准字段恢复只开放给明确验证组合，并标明不会恢复的私有项。
3. 若业务必需的浓度、切刀、钱箱等私有项无法恢复，则阻断或标记“不完整，不得作为验收成功”，不提供静默尽力恢复。
4. 以目标驱动生成有效基准并完成能力检查/合并；合并返回失败或请求字段被不可接受地改写时，在写入前终止，系统保持未修改。
5. 展示应用计划并取得确认。Level 8 如需提权，由用户明确触发 helper；拒绝提权则停止且不修改。
6. **备份必须先于写入**：Level 9 应用备份当前用户 Level 9；Level 8 应用同时备份 Level 8 与原交互用户 Level 9。备份失败则不写入。
7. 写入来源对应的同一层，`SetPrinter` 后按相同 Level 回读。公共请求字段、结构长度和私有段摘要按目标驱动验证规则检查；不可接受的差异视为技术失败。
8. 写入或回读失败自动进入回滚，分别恢复本事务备份的层并再次回读。UI 必须区分“已回滚”和“回滚失败”；后者展示备份位置、当前状态和手动恢复入口。
9. 技术应用通过后，状态为“已应用，待测试”，而不是直接显示“验收成功”。

### 5. 测试、人工结果与恢复选择

- V1 内置固定 GDI 测试页，包含工具版本、目标队列、配置名称、时间、基础图形与文字；通过 `CreateDC` 显式携带工作/已应用 DEVMODE，不用 RAW 测试冒充 DEVMODE 验证。
- 作业 API 返回只记为“测试作业已提交/提交失败”。提交成功不证明出纸、浓度、切刀或钱箱正确。
- 测试提交失败或人工纸面不满意时，配置保持已应用状态，用户选择“保留配置”“重新测试”或“恢复应用前备份”；不自动回滚。
- 人工确认区按实际用途提供纸张、浓度、切刀、钱箱、其他等检查项；虚拟打印机只记录输出文件/作业结果，不出现虚假的物理通过。
- 业务票据模板仍由业务系统手动打印验收。V1 不接入、不修改业务打印链路；单次打印显式携带 DEVMODE 的长期改造另立项目。

### 6. 统一状态语义

至少区分：`未修改`、`校验失败`、`不兼容`、`等待提权`、`备份失败`、`应用失败`、`回滚成功`、`回滚失败`、`已应用/回读通过`、`测试提交失败`、`测试作业已提交`、`待人工确认`、`人工验收通过`、`已应用但测试未通过`、`用户已恢复备份`。

- “已应用/回读通过”是技术状态，不等于业务验收成功。
- “受限标准字段恢复”必须始终附带未恢复项，不在后续页面简化成完整成功。
- 回滚失败是独立高优先级状态，不能覆盖原始应用错误；诊断中同时保留两组错误。

### 7. 客服与现场验收

**客服制作/分发验收**：原厂窗口取消不落盘；确认只改工作副本；导出重开校验通过；来源元数据只读；备注可编辑但不影响兼容；受保护内容改动被发现；不匹配配置被拦截；全程无需服务端。

**现场恢复验收**：目标驱动已安装且队列可用；同层应用；备份先于写入；拒绝提权/备份失败不写；写入/回读失败自动回滚；Level 8 操作同时能恢复当前用户 Level 9；内置 GDI 测试和业务打印分别记录；人工确认后才标记验收通过；恢复备份后再次回读。

**自动化与实机分工**：虚拟打印机自动覆盖可虚拟验证的流程和故障注入；真实设备的私有功能与纸面效果逐组合手动签收。跳过不具备条件的自动用例必须显示原因，不能计入通过。

### 8. V1 边界

包含直接备份、模板制作、原厂窗口、导出、导入、同层应用、自动备份、技术失败自动回滚、回读、内置 GDI 测试、人工结果记录和手动恢复备份。不包含跨层转换、业务模板集成、自动安装驱动/端口、系统默认打印机切换、云端下发或长期打印链路改造。
