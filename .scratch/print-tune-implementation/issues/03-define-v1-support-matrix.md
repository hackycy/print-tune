# 确定 V1 现场环境与硬件支持矩阵

Type: grilling
Status: resolved
Blocked by: none

## Question

V1 必须支持哪些 Windows 版本、系统架构、Windows 用户/权限场景、打印机品牌型号、驱动名称与版本、连接方式及典型打印用途？首批可用于开发和纸面验收的 2～3 类真实设备是什么，由谁提供？明确“同型号同驱动可恢复”的可测试边界，以及不在支持矩阵内时产品应提示还是阻断。

## Comments

- 2026-10-24 用户输入：目标为 Windows 7 / 10 / 11，x86 + x64。具体打印机品牌型号、驱动版本、连接方式和可提供实机仍未给出；该选择与 .NET 8 存在运行时冲突，转票据 04 先收敛。
- 微软官方当前说明：.NET 8 不支持 Windows 7 / 8.1；Windows 7 上最后支持的现代 .NET 是 .NET 6，且其支持已于 2024-11-12 结束。来源：https://learn.microsoft.com/zh-cn/dotnet/core/install/windows?pivots=os-windows
- 2026-10-25 用户补充：真实打印机采用手动实机验收；自动化测试自行获取当前已有的打印机，例如 Microsoft Print to PDF，不要求自动化测试配备实体票据机。

## Answer

V1 支持矩阵按“产品运行矩阵、自动化测试矩阵、实机验收矩阵”三层定义，不再以自动化测试覆盖实体硬件能力为前提。

### 1. 产品运行矩阵

- 操作系统：Windows 7 SP1、Windows 10、Windows 11。
- 架构：x86 与 x64 分别构建、分别测试；不承诺 ARM64。
- 运行时：使用 .NET Framework 4.8 + WPF；Windows 7 的离线运行时与必要系统更新纳入部署验收。
- 权限场景：覆盖标准用户与具有打印队列管理权限的用户；Level 8/9 的最小权限和提权行为由后续实机原型验证。
- 队列：本地 USB/网口队列是首要场景；共享/远程队列不因为 Win32 API 可枚举就自动承诺 Level 9 等能力，须单独验证。

### 2. 自动化测试矩阵

- 单元测试不依赖任何真实队列，通过 Win32 互操作抽象与假实现覆盖配置包校验、兼容决策、状态迁移、备份计划和错误映射。
- 集成测试运行时枚举当前已有打印机，不硬编码唯一队列名称；优先选择 `Microsoft Print to PDF`，其次可选择 `Microsoft XPS Document Writer` 或测试环境已有的其他合适虚拟队列。
- 测试先探测队列、驱动和所需能力，再选择可执行用例；不存在适用打印机时标记为“跳过及原因”，不得伪装为通过，也不自动安装打印机或驱动。
- 虚拟打印机可验证枚举、元数据读取、DEVMODE 完整复制、配置包往返、部分标准字段合并、备份/回滚编排和 GDI 作业提交；不得据此宣称实体票据机的浓度、切刀、钱箱或纸面兼容。
- 当前规划环境对外部打印机查询受执行沙箱限制，因此不记录一份静态“本机已有”清单；由未来测试程序在目标测试机上自行发现。

### 3. 手动实机验收矩阵

- 每个准备支持完整私有恢复的“设备型号 + 真实驱动文件版本 + 驱动环境/架构 + Windows 版本 + 相关业务打印路径”组合，都必须有手动验收记录。
- 至少覆盖：完整导出、目标机导入、Level 8/9 备份与回滚、同层回读、原厂界面复核（可用时）、业务路径测试票，以及纸张/浓度/切刀/钱箱等实际使用项的人工确认。
- 未通过手动验收的组合不进入完整恢复白名单；同驱动名、版本和架构本身不足以放行。
- 标准字段降级只对明确验证过的来源/目标组合开放；其他未知组合阻断，不使用“型号接近”或字符串相似度猜测。
- 手动实机验收是相应硬件组合的发布门槛，但不要求每次自动化构建都连接实体设备。

### 4. 支持边界

- 工具可在支持的操作系统上枚举未知打印机，但“能枚举”不等于“允许完整恢复”。
- 未知组合默认阻断完整私有恢复；仅当存在明确且已验证的迁移规则时才允许受限标准字段降级。
- 测试打印的 API 成功只代表相应技术阶段成功，最终物理效果由人工验收记录确认。
