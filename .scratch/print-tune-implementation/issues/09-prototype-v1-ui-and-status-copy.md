# 制作 V1 页面流程、状态展示与关键文案原型

Type: prototype
Status: resolved
Blocked by: 06

## Question

如何将已确定的操作闭环制作成可评审的 WPF 页面/线框原型？需要覆盖打印机与来源层选择、备份/模板制作、导入兼容摘要、应用前确认、提权、备份/写入/回读/回滚进度、受限恢复项、GDI 测试与人工确认、回滚失败和手动恢复入口；固定“未修改/已应用/已提交/人工验收”等状态文案，避免笼统成功和误导性强制按钮。

## Answer

已制作可点击原型：[V1 页面流程、状态展示与关键文案](../prototypes/v1-ui-flow.html)。原型不访问真实打印机，内嵌脚本已通过语法检查。用户评审三种结构后，明确选择 **A · 分步向导** 作为 V1 默认主界面。

### 1. 主界面结构

采用四步向导：

1. **选择任务**：导入配置、备份现有、制作模板；选择目标队列与 Level 8/9，明确同层来源和目标。
2. **兼容检查**：显示来源/目标驱动、完整性、来源未验证、完全/受限/不兼容及未恢复项。
3. **备份与应用**：展示备份范围、目标用户、提权需求、写入/回读进度；只有本步才允许修改系统。
4. **测试与验收**：内置 GDI 测试、作业状态、人工物理检查和保留/恢复选择。

右侧固定显示“当前状态”和“执行进度”，即使用户返回上一步也能看出系统是否已修改。运维工作台式的队列/诊断同屏布局不进入默认主流程；后续可在“诊断详情”中复用其信息，但不增加 V1 主导航。

### 2. 固定状态文案

| 技术/业务阶段 | UI 主文案 |
|---|---|
| 尚未写入 | `未修改` |
| 等待 Level 8 提权 | `等待提权 · 配置未修改` |
| 取消提权 | `未修改 · 提权已取消` |
| 写入与同层回读通过 | `已应用，回读通过 · 待测试` |
| 写入失败且恢复成功 | `应用失败 · 已回滚` |
| 自动恢复失败 | `应用失败 · 回滚失败` |
| 测试提交失败 | `已应用 · 测试提交失败` |
| 测试提交成功 | `测试作业已提交 · 待人工确认` |
| 人工不接受纸面结果 | `已应用 · 纸面结果未通过` |
| 用户主动恢复 | `已恢复应用前备份` |
| 最终人工通过 | `人工验收通过` |

不得用单独“成功”“导入成功”覆盖这些阶段。用户主动恢复与系统应用失败后的自动回滚必须使用不同文案。受限恢复始终附带“未恢复哪些私有项”，不能在最后一步简化成完整恢复。

### 3. 关键交互约束

- 原厂界面确认只更新工作副本，页面持续显示“系统配置未修改”；导出也明确不修改系统。
- 不兼容页只提供重新选择/重新制作，不提供“强制执行”。
- Level 8 应用前显示将备份 Level 8 与当前用户 Level 9；Level 9 显示当前交互用户，不能经 helper 写入。
- 提权由用户明确允许；拒绝后回到未修改状态，不自动重试。
- 写入/回读失败自动回滚；回滚失败页保留原始错误、回滚错误、事务 ID、备份位置和手动恢复步骤，禁止反复点击应用。
- 测试页说明 GDI 显式 DEVMODE 与物理效果的差别。人工通过前需确认适用检查项，不适用项需显式标记，而不是默认全选。
- 测试/纸面失败后提供“恢复应用前备份”“保留当前配置”“重新测试”，不擅自回滚。
- 全流程不改变 Windows 默认打印机，不出现云端、驱动安装或端口创建入口。

### 4. 原型覆盖场景与 WPF 落地

已覆盖完全匹配、受限恢复、不兼容、写入失败回滚、回滚失败和测试提交失败，并支持 Level 8/9、备份、模板工作副本和人工结果。WPF 实现时使用同一状态机驱动步骤、按钮可用性和文案，禁止各页面自行推断状态；诊断面板只读展示应用服务结果。

原型语法已复查。视觉稿只冻结信息结构与交互，不要求把 HTML 样式逐像素搬入 WPF；桌面 DPI、键盘导航、焦点、长驱动名、中文/英文溢出和 Win7 字体表现进入后续 UI 实现验收。
