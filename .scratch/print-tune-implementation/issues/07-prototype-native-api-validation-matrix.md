# 用最小原生验证器确认 P0 实机行为

Type: prototype
Status: resolved
Blocked by: 03, 04

## Question

在选定的技术栈和首批真实设备上，构建不进入产品交付的最小 API 验证器，能否证实 Level 8/9 最小权限、Level 8 对 Level 9 的影响范围、完整 DEVMODE 导出/合并/同层回读、原厂窗口 OK/Cancel、目标能力查询和 GDI 测试打印的实际行为？需要记录哪些结构化结果，才能把精确设备/驱动组合加入完整恢复或标准字段降级支持矩阵，并暴露必须调整架构的驱动差异？

## Answer

验证方案已固化为可点击原型：[P0 原生 API 验证矩阵](../prototypes/p0-validation-matrix.html)。原型不调用 Win32、不修改打印机，已通过内嵌脚本语法检查。它解决的是“需要哪些证据、如何记录和如何判定”的设计问题；**没有把任何真实设备标记为兼容，实际白名单仍须由原生探针和人工验收结果生成。**

### 1. 原生验证器的安全边界

正式实现一个独立控制台探针，不进入 PrintTune 产品发布包，默认只读：

- 自动枚举现有队列；只读集成测试可优先选择 Microsoft Print to PDF 等虚拟队列。
- 读取队列/驱动身份、Level 8/9、完整 DEVMODEW、目标能力和表单，输出结构化报告。
- 原厂窗口和 GDI 测试必须显式选择目标队列；原厂确认只产生工作副本，不隐式 `SetPrinter`。
- 任何 Level 8/9 写入、回滚或故障注入都必须同时提供精确队列名和独立确认参数；禁止“自动选任意打印机并写入”。
- 写入前先导出备份并验证可回滚；Level 8 还保存原交互用户 Level 9。另一用户的影响必须在独立登录会话中验证，不能自动猜测。
- 探针报告不保存私有 DEVMODE 字节，只保存长度、必要公共字段和 SHA-256 摘要；原始备份单独受控保存。

### 2. P0 证据组

原型固定 11 个检查项：

1. 队列、端口、真实驱动文件版本与环境元数据。
2. 标准用户/目标 ACL 下 Level 8/9 最小读取权限。
3. 完整 DEVMODEW 探长度、深复制、驱动合并及输出边界。
4. DeviceCapabilities、分辨率、纸张、纸盒与 EnumForms 几何信息。
5. 原厂窗口 IDOK、IDCANCEL、失败及工作副本隔离。
6. Level 9 同用户写入、同层回读和回滚。
7. Level 8 直接/提权写入、拒绝提权和同层回滚。
8. Level 8 对当前及另一用户 Level 9 的影响范围。
9. GDI 显式 DEVMODE 测试与作业状态；RAW 不作为替代证据。
10. 写入失败、回读差异、helper 超时/崩溃及双层备份回滚。
11. 真实业务路径与纸张、浓度、切刀、钱箱等人工纸面结果。

### 3. 结构化报告契约

每次运行至少记录：

- `runId`、探针版本、时间、测试人、设备型号、队列、连接方式、Windows 版本、进程/驱动环境和真实驱动文件版本。
- 来源层、当前交互用户作用域的匿名标识、业务打印路径、设备类型（实体/虚拟）、是否依赖私有参数。
- 每个 API 步骤的操作名、访问掩码、Level/fMode、返回值、`GetLastError`、所需/实际缓冲区长度、耗时与阶段结果。
- DEVMODEW 的 `dmSize`、`dmDriverExtra`、总长度、`dmFields`、被请求公共字段、合并/回读后的语义差异，以及私有段摘要；不把逐字节不同直接等同失败，也不忽略无法解释的差异。
- 备份 ID、写入事务 ID、回滚结果、原始应用错误和独立回滚错误。
- GDI 作业 ID/状态、虚拟输出文件位置（如适用）、人工物理检查项与验收人。
- 单项状态严格为 `pass / fail / skip / not-run`；`skip` 和 `not-run` 均不计为通过。

### 4. 白名单判定

- **完整恢复候选**：来源/目标精确身份一致，并且所有适用 P0 项通过，包括相应层的写入/回滚和实体业务纸面验收。只读虚拟打印机结果不能证明实体私有功能。
- **仅标准字段恢复候选**：明确迁移组合的能力检查、同层写入/回读、GDI 与失败回滚通过，并且业务不依赖未恢复的私有参数。若仍必需浓度、切刀、钱箱等私有项，则阻断。
- **证据不足**：任何必需项未执行或跳过；不能进入白名单。
- **阻断**：任一适用必需项失败，或身份/私有依赖不满足。驱动名称、版本和架构一致但没有后续证据，永远只得到“证据不足”。

### 5. 对正式架构的反馈

- Win32 适配层必须返回分阶段调用轨迹和结构化错误，而不能只返回布尔值。
- 回读比较需要按驱动积累“可接受规范化差异”规则；未知差异进入人工复核，不写死全局逐字节相等/不等策略。
- helper 协议需要事务 ID、超时、崩溃恢复和原始/回滚双错误。
- Level 8 备份模型必须包含当前用户 Level 9；另一用户影响属于独立手动测试。
- 测试打印状态与人工物理结果分离；支持矩阵记录业务路径，不能把 GDI 结果外推到 RAW/厂商 SDK。

后续实现原生探针时，直接以原型中的检查项和报告契约作为验收输入；每个真实组合的报告通过评审后，才分别加入完整恢复或标准字段恢复支持矩阵。
